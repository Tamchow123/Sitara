## Known issues / notes for whoever wires up the asset pipeline

- **`silhouette:kali`, `silhouette:kalidar`, `silhouette:farshi-gharara`, `silhouette:classic-sharara`** —
  the `imgMap()` source in `Sitara Questionnaire.dc.html` spells these paths with a plain hyphen
  (e.g. `Lehenga - Panelled kali.png`), but the actual files on disk use an em dash (`—`) instead
  (`Lehenga — Panelled kali.png`). This is a bug in the original prototype's fetch path — it would 404
  if ported literally. The table above already points at the real filenames.
- **`silhouette:front-open`, `silhouette:jacket-anarkali`, `sleeves:sl14`, `midriff:midSheer`** — the
  prototype's `imgMap()` resolves these one directory level above `gaps/` (a quirk of the design tool's
  own folder layout). In this `images/` folder the actual files live inside `gaps/` (or, for `sleeves:sl14`,
  inside `09-sleeves/`) — the table above points at their real location here.
- **`silhouette:half-saree`, `head:headHijab`** — the prototype references cleaned-up filenames under a
  `gaps/clean/` subfolder that doesn't exist in this `images/` folder. The same photos exist here under
  their original (messier) names — `gaps/Saree — Half saree (langa voni).png` and
  `gaps/Hijab — full coverage, no hair shown.png` — and the table above points at those.
- **Known content gaps** (per the design README — these are real placeholder-quality shots, not a
  matching error): `silhouette:straight` (straight-cut lehenga), `silhouette:pre-stitched` (pre-stitched
  saree), `silhouette:angrakha` (angrakha kameez), `silhouette:longline` (long-line kameez). Treat these
  as candidates for reshooting/regenerating later.
- **`00-references/`** — 2 files (`sitara__flux2max__embroidery__zardozi.jpg`,
  `sitara__flux2max__necklines__v_neck.jpg`) aren't referenced by any questionnaire screen. Filenames
  suggest they're FLUX image-generation reference shots rather than UI photography — moved to `_unused/`
  along with everything else unreferenced, but worth a look before deleting for good since they may be
  useful for tuning the actual Replicate/FLUX generation pipeline later.
- **`01-landing-page/`** — empty; the Home screen currently reuses two ceremony photos
  (`02-ceremonies/sitara__ceremonies__baraat__v2.jpg`, `…walima__v1.jpg`) as its hero images rather than
  dedicated landing photography. Left as-is.
- **`03-garments/sitara__garments__lehenga__v1.webp`** — a `.webp` duplicate of `lehenga__v1.jpg`, not
  referenced anywhere; moved to `_unused/`.
